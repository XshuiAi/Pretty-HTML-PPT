# 内容转 HTML PPT

## 目标

将用户提供的网页、Markdown、文档、逐字稿或纯文本转成一个可演示的 HTML PPT。输出必须包含：

1. 可核对的 slide 大纲；
2. 简洁的可见页面内容；
3. 每页对应的演讲稿；
4. 可继续在浏览器中编辑、演讲与导出 PPTX 的 HTML deck。

## 解析原则

- 先保留原始内容的事实、数字、人物、时间、结论和链接；不要以“整理”为名编造论据。
- 将长内容压缩为一个中心判断、三到五个支撑点和清晰的结论/行动。
- 每一页只服务一个判断或信息任务。避免把文章段落逐段搬上 slide。
- 将无法在 5 秒内读懂的解释放进 .speaker-notes，而不是继续压缩字号。
- 重要原始链接在相关页或结尾页保留为可点击来源。

## 推荐工作顺序

1. 读取来源，列出关键事实、主张、证据、反例/限制与可保留链接。
2. 写一个 5–12 页的大纲，标明每页的标题、页面任务、来源证据和演讲稿目标。
3. 先让大纲呈现叙事顺序：封面 → 背景/问题 → 核心判断 → 证据/结构 → 含义/行动 → 结论。需要时加入章节页、案例页、数据页或附录。
4. 先根据内容选择视觉系统，再使用 `scripts/create_deck.py /absolute/output --style <base|editorial-ink|swiss-grid>` 初始化独立 deck；把示例页面替换为实际内容，并为每个 `.slide` 保留 `data-slide`。选择规则见 `visual-systems.md`。
5. 为每页写 80–180 字的演讲稿：开场句、要点解释、证据或例子、自然过渡。演讲稿应基于用户提供的内容，不要假装掌握来源以外的信息。
6. 运行注入与验证。确认每页有一个可见主判断，演讲稿没有重复页面全文。

## 大纲格式

在开始写 HTML 前，以此格式呈现或保存大纲：

| 页码 | 标题 | 页面任务 | 可见内容 | 演讲稿要点 |
|---|---|---|---|---|
| 1 | 核心判断 | 建立主题 | 标题、来源、对象 | 开场与目标 |
| 2 | 背景/问题 | 对齐语境 | 关键事实或矛盾 | 为什么现在需要关注 |
| 3–N | 支撑内容 | 证明判断 | 证据、比较、过程或案例 | 解释、限定与过渡 |
| N+1 | 结论 | 留下行动 | 一句话结论、下一步、来源 | 收束与邀请讨论 |

## 交付检查

- 内容源有链接时，deck 中保留原链接或明确来源说明。
- 所有页面都带 .speaker-notes 或 data-speaker-notes。
- 语义结构和编辑运行层分离：不要为了可编辑性改写固定视觉内容。
- 输出目录可直接交付；不要引用本机绝对路径或外部未授权资产。
